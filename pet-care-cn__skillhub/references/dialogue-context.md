# 多轮对话上下文(v1.2+)

> **版本**:v1.2
> **作用**:让 skill 在多轮对话中保持上下文一致性(不丢前轮关键事实,正确识别 follow-up 问题)
> **存储位置**:本文件描述逻辑,实际存储由 skill 运行环境负责(session memory / KV store / DB)

## 1. 适用范围

v1.2 让 pet-care-cn 支持多轮对话,例如:
- 第 1 轮:用户问"我家 3 月英短幼猫刚到家" → skill 给典型建议
- 第 2 轮:用户追问"那驱虫什么时候做?" → skill 不再要求用户重新输入 5 字段,自动继承前轮的 species=cat + age_stage=junior,只更新 topic=dv
- 第 3 轮:用户说"第 2 次驱虫后它吐了" → skill 记录症状 + 触发 P0/P1 评估

## 2. session state 结构

每个用户会话存以下结构(由运行环境实现):

```json

  "created_at": "2026-08-16T16:30:00Z",
  "updated_at": "2026-08-16T16:35:00Z",
  "turns": [
    {
      "turn_id": 1,
      "user_input": "我家 3 月英短幼猫刚到家",
      "extracted_fields": {

        "topic": "arrival",
        "age_stage": "junior",
        "context": {"品种": "英短", "月龄": "3 月"}
```

## 3. 字段继承规则

### 3.1 哪些字段会继承

| 字段 | 继承? | 说明 |
|---|---|---|
| `species` | ✅ 高 | 用户通常 1 个会话只问 1 种宠物 |
| `age_stage` | ✅ 高 | 同上,除非用户说"我家还有一只 5 岁猫" |
| `context.品种` | ✅ 高 | 一次会话 1 只宠物 |
| `context.既往` | ✅ 中 | 健康状态可能变化,但通常稳定 |
| `topic` | ❌ 不继承 | 每轮可能问不同主题 |
| `question` | ❌ 不继承 | 每轮新问题 |
| `images` | ❌ 不继承 | 每轮可能发不同图 |

### 3.2 继承优先级

1. **本轮明确指定**(最高):用户说"我家狗" → species=dog 覆盖
2. **前轮 session state**:继承前轮
3. **反问用户**(最低):继承不可用时反问 1 次

## 4. follow-up 问题识别

### 4.1 常见 follow-up 模式

| 用户输入模式 | 识别为 | 主题推断 |
|---|---|---|
| "那 [X] 呢?" | follow-up | 继承 species+age,topic 取决于 X |
| "如果是 [Y] 怎么办?" | follow-up | 继承 species+age,topic=diet/beh/arrival |
| "[前轮答案] 之后呢?" | follow-up | 继承 + topic 跟随 |
| "我没说 [症状],但有 [Z]" | 新主题(可能升级) | 继承 + topic 重新判断 |
| "[话题] 再详细点" | 追问 | 继承 + topic 同前轮 |
| "我家 [另一只宠物] ..." | 多宠物 | 新增 species 记录 |

### 4.2 反例(不是 follow-up)

| 用户输入 | 不是 follow-up | 处理 |
|---|---|---|
| "我家有只兔子" | 新增 species=rabbit | 多宠物记录,不影响前轮 cat 会话 |
| "塔罗怎么玩" | 完全无关 | 礼貌说明 skill 范围,或忽略前轮 |
| 30 分钟后的新问题 | 可能是新会话 | 由运行环境决定是否同 session |

## 5. 一致性保证(本 skill 必须遵守)

### 5.1 关键事实不丢失

前轮确立的关键事实(英短 HCM/3 月龄首免/已绝育公猫),**后轮必须继续使用**,不要让用户重新解释。

**反例**:
- 第 1 轮:用户说"我家 3 月英短" → skill 输出含"英短 HCM 筛查"
- 第 2 轮:用户问"那绝育什么时候做?" → skill 不应再问"什么品种?"
- 应继承前轮的 species=cat + context.品种=英短

### 5.2 矛盾检测

如果后轮信息与前轮**矛盾**(用户说"我家 3 月英短" → 后轮说"我家 1 岁田园"),**反问 1 次确认**,不要默默覆盖。

### 5.3 升级路径

**症状升级**:前轮是 P2 观察,后轮用户说"加重了/出现新症状" → 升级到 P1/P0,转兽医

**主题升级**:前轮是 P1 转介,后轮用户说"已经看过医生了" → 主题可能转为"已确诊疾病管理",加载对应模板

## 6. 隐私与存储边界

1. **session 数据不写入永久记忆**:对话结束后清理
2. **不跨用户共享**:session_id 隔离
3. **不外发**:前轮关键事实不上传到第三方
4. **保留期限**:默认 24 小时(可由运行环境配置)
5. **用户可清空**:用户主动要求时立即清空 session state

## 7. 上下文摘要(给 LLM 用的精简版)

每轮开始时,运行环境给 LLM 注入一段精简的 session context:

```
[Session Context]
用户宠物: 1 只,英短,3 月龄
当前位置: 第 3 轮对话
前轮主题: arrival → dv → ?
已知关键事实:
- 英短(品种,前轮确定)
- 3 月龄(年龄,前轮确定)
- 首养首宠(前轮用户自述)
- 6/8/10/12 周龄首驱(前轮 skill 输出)
- 8/12/16 周龄首免妙三多(前轮 skill 输出)
本轮用户输入: "<新问题>"
```

LLM 看到这段,就能在不完全重复输入的情况下继续对话。

## 8. 错误处理

### 8.1 继承冲突

- 用户第 1 轮说"猫",第 2 轮说"狗" → 反问"你刚说的是猫,现在说狗,是另一只宠物,还是纠正?"
- 处理后,创建新 session 或在同 session 加新宠物记录

### 8.2 session 过期

- 超过 24 小时 → 视为新会话,要求用户提供完整 5 字段
- 用户主动说"重新开始" → 同上

### 8.3 上下文超长

- 关键事实超过 20 条 → 触发 LLM context 窗口限制
- 解决:运行环境压缩旧事实为摘要,只保留最近 3-5 轮的关键事实

## 9. 与现有 5 字段关系

| 5 字段 | 多轮中的作用 |
|---|---|
| `species` | 继承 + 反问 |
| `topic` | 每轮重新推断(可能与前轮相同/不同) |
| `age_stage` | 继承 + 反问 |
| `question` | 每轮新 |
| `context` | 累加(品种/既往/已确诊/已用药物),后轮不删除前轮 |
| `images` | 每轮新 |

## 11. v1.2 已知限制

- **跨 session 不共享**:用户从新会话开始,前轮上下文清空
- **不支持图片上下文继承**:用户第 1 轮发了皮肤病图,后轮再发图,两张图独立分析
- **不支持跨宠物关联**:用户先问猫,后问狗,不会自动关联"多宠物家庭"
- **环境依赖**:session storage 需运行环境支持(SKILL.md 仅规定逻辑,实现由 runtime 决定)
- **隐私兜底**:用户数据不持久化,所有 session 状态均在内存或短期存储
