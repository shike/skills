# 案例实战教练（fde-case-coach · FDE 实战营 WS1）

> AI 扮演一个"有底牌的制造业客户"，带学员走完 **需求访谈 → 粗版 PRD → HTML 原型** 的完整需求侦察——无论访谈好坏，20 轮对话保底交付。

## 它解决什么问题

需求访谈是 FDE 最难练的一环：没有真实客户陪你练，学员问两句就冷场，产出没人兜底。本 Skill 内置**双角色编排 + 保底机制**：

- **阶段一（第 1–5 轮）你是"客户"**：默认扮演发起人小周，学员点到就切换资深报价工程师王工。隐藏信息库**不问不答、表层问题只给表层答案、好问题才给真金**——逼学员练"怎么问"，而不是等答案
- **阶段二（第 6–15 轮）切换教练**：先出事实覆盖表，再按固定骨架逐段生成粗版 PRD
- **阶段三（第 16–20 轮）生成 HTML 原型**：3–5 屏、每屏右上角标注对应 PRD 条目

## 设计红线（Skill 不会妥协的地方）

- **产出边界**：这份 PRD 是"侦察全景"不是"决策书"——一期范围、计费模式、验收标准一律以"开放问题"出现（必须 ≥3 条），绝不替 WS2/WS3 抢答
- **事实闭环**：案例的每条书面事实，要么被引用、要么被明确排除
- **人在环常识**：凡"出错要人担责"的环节，功能上必须留人工确认——但何时自动化，只记入开放问题
- **不停机原则**：学员冷场就说"都可以"？按教练建议继续推进，产出义务优先于互动体验

## 使用方法

1. 把 `SKILL.md` 全文粘贴给 WorkBuddy（或其他 Agent 助手），附一句"请加载这个 Skill"
2. 粘贴 `assets/案例一页纸_恒润精工.md` 全文（或你自己的客户背景），说"开始"
3. 对话自动进入第 1 轮；详细启动话术见 `assets/PROMPT_启动.md`

> 想换自己的案例？把案例一页纸换成你的客户背景即可，Skill 的角色与底牌结构需按新案例同步调整。
