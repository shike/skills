# 报告 Schema 定义

10 节报告的字段结构。LLM 读取本文件即可知道要填充哪些字段。5 块必加规则（数据时效/标签系统/3x3 矩阵/概率影响/行动清单+资金）见 `SKILL.md` Step 0.5-3.2。

**字段难度**（数据获取）：🟢 易（公开搜索大概率能拿到）/ 🟡 中（部分情况下能拿到）/ 🔴 难（公开搜索拿不到，搜不到写「未找到公开数据」）

## 各节字段定义

### 一 摘要卡
- `verdict`（🟢/🟡/🔴） + `verdict_reason`（1 句） + `conclusion_3sentences`（3 句话：现状+财务+行动） + `top_3_risks` + `key_metrics`（3-5 个核心数字）

### 二 点位信息
- `business_district`（商圈名） + `location_history`（同位置历史门店 名称/业态/存活时长/关店原因） + `address_parsed`（街道/楼层/区域） + `transportation`（地铁/公交/停车）

### 三 周边竞品
- `top_5`（周边 5 家同品类：名称/距离/评分/客单价/经营时长） + `density_grade`（低/中/高） + `top_brand_info`（头部竞品信息）

### 四 人流估算
- `daily_traffic_estimate`（工作日/周末/节假日） + `peak_hours` + `seasonal_variation`（旺季/淡季月份）

### 五 客群画像 🔴
🔴 无 web_search 数据源。字段定义保留，渲染时如无数据写「未找到公开数据」，建议用户委托第三方调研。

- `age_distribution` + `occupation`（学生/白领/家庭/游客） + `consumption_scenarios`（早通勤/午市/下午茶/夜宵/聚会） + `willingness_to_pay`（核心区间 6-30 元）

### 六 同类门店
- `closed_stories`（2024-2026 + 同品类 + 同城市） + `survival_brands`（存活较好的同类品牌）

### 七 风险评估
- `demolition_risk`（低/中/高 + 依据） + `policy_risk`（低/中/高 + 依据） + `risk_score_card`（6 维概率×影响矩阵，见字段 22）

### 八 财务测算
- `rent_estimate`（基于 58/安居客挂牌价） + `breakeven_months_estimate`（回本周期） + `breakeven_volume`（盈亏平衡日销量） + `cashflow_6months`（前 6 月现金流）

### 九 谈判筹码
- `rent_benchmark`（同商圈 中位数/P25/P75） + `rent_negotiation_room`（压价空间） + `can_negotiate`（可谈判点 4-6 个：租金/免租期/装修期/转让费） + `rent_listings_58`（5-10 个公开房源） + `talking_points`（≥3 条话术，见字段 24）

### 十 行动清单
- `must_verify_on_site`（必须现场验证） + `can_negotiate`（可谈判点） + `must_reject`（必须否决的红线，3-5 条）
- 3 类分：立即做（签约前 1-2 周）/ 验证（签约前 1 周）/ 否决（任一命中红线）。每条 4 维评估：成本/收益/风险/决策可执行性。
- 资金准备清单（报告独立章节）见 SKILL.md Step 3.2。

### 附录 A：换品类建议（verdict = 🔴 且原因为财务时渲染）

- `top_3_categories`（3 个：品类/理由/预期月净利变化/数据来源） + `swap_caveats`（换品类的注意事项）
- **目的**：用户方案财务不成立时给 Plan B。

### 附录 B：数据局限（始终渲染）
LLM 整理：哪些字段依赖 web_search / 行业基准 / 搜不到公开数据 / 建议用户实地验证。

### 附录 C：决策深度分析框架（8 项，始终渲染）

| 子节 | 内容 | 约束 |
|---|---|---|
| C-1 品类适配性分析 | `adaptation_score` + `adaptation_reasons`（3 个具体理由） + `top_3_alternative_categories` + `evidence_sources` | 软建议 |
| C-2 差异化空间分析 | `price_band_gap` + `customer_scenario_gap` + `category_format_gap` | 软建议 |
| C-3 签约前法律/物业核查 | 8 项硬约束（产权/执照/合同/历史纠纷/含项/转让/免租/退出）— 命中任一红线必须放弃 | **硬约束** |
| C-4 历史经营情况调研 | `previous_tenants` + `survival_rate_estimate`（5 年存活率） + `high_failure_reasons` + `current_landlord_intent` | 软建议 |
| C-5 位置战略价值评估 | `customer_reach` + `competitive_barrier`（同位置 3-5 年保护） + `format_potential` | 软建议 |
| C-6 个人/资源层风险评估 | `funding_runway_months` + `industry_experience_years` + `core_team_stable` + `commute_minutes_to_shop` | 软建议 |
| C-7 退出/止损机制规划 | `exit_cost_estimate` + `stop_loss_line_months` + `equipment_resale_value` + `transferability_estimate` | 软建议 |
| C-8 风险对冲/保险方案 | `public_liability_insurance` + `property_insurance` + `business_interruption_insurance` + `emergency_fund_months` + `income_diversification` | 软建议 |

## 字段 18：盈亏平衡分析

**公式**：
```
盈亏平衡月销量 = 固定成本 / (客单价 - 单位变动成本)
  固定成本 = 月租 + 人工 + 水电 + 摊销
  单位变动成本 = 客单价 × 食材成本率
```

**3x3 敏感性矩阵**：见 SKILL.md Step 2.5.1。

每个格子标"月净利润数字"（如 `+0.4 万` / `-0.5 万`）。关键发现必须标：亏损/临界/健康场景数 + 盈亏平衡日销量。

## 字段 19：前 6 月现金流预测

**假设**：第 1 月 30% 爬坡 → 第 5-6 月 100%。

表格结构：月份 / 月营收 / 月成本 / 净现金流 / 累计现金流。关键提示：开业一次性投入 / 月固定成本 / 现金流回正月 / 准备资金建议。

## 字段 20：公开房源

字段：`address` + `area_sqm` + `monthly_rent_yuan` + `price_per_sqm_per_day` + `source`（58/安居客链接） + `property_type`（临街/商场内/社区底商）

至少 5-10 个房源用于中位数/P25/P75 计算。

## 字段 21：周边竞品外卖月销

字段：`brand` + `address` + `meituan_monthly` + `eleme_monthly` + `min_order_yuan` + `source`

至少 1 个竞品的外卖数据。web_search 拿不到具体美团/饿了么页面，标"行业基准推算"或"现场蹲点"。

## 字段 22：风险评分卡

**概率 × 影响矩阵**：见 SKILL.md Step 2.5.2。6 维度：拆迁 / 政策 / 竞品 / 客流 / 财务 / 品类适配。

## 字段 23：季节性指数 + 生命周期曲线

字段：`seasonality_curve`（12 个月系数 0.5-1.5，1.0 为基准） + `peak_months` + `low_months` + `lifecycle_curve`（1-12 月爬坡/稳定） + `critical_months`（[3, 6]）

**行业基准**（LLM 内部查表）：

| 品类 | 旺季月份 | 淡季月份 | 范围 |
|---|---|---|---|
| 奶茶 | 5-9 月 | 12-2 月 | 0.7-1.3 |
| 咖啡 | 10-3 月 | 6-8 月 | 0.8-1.2 |
| 快餐 | 全年稳定 | 2 月 | 0.9-1.1 |
| 麻辣烫 | 10-3 月 | 6-8 月 | 0.8-1.2 |
| 烘焙 | 10-12 月 | 6-8 月 | 0.9-1.15 |
| 正餐 | 9-2 月 | 3-4 月 | 0.85-1.2 |

## 字段 24：谈判话术

每条话术结构：`point` + `script` + `evidence` + `expected_outcome`（成功/部分成功/被拒）

至少 3 条话术（基于公开房源压租金 / 基于关店案例压租金 / 争取免租期）。

## 渲染规则（Hard Requirements）

1. 字段缺失：写「未找到公开数据」而非编造
2. 来源标注：每个事实至少 1 个来源链接
3. 数字精度：免费版数字给区间，不强行精确
4. 必加内容：数据时效分布表（报告头部） + 完整标签系统 + 3x3 矩阵 + 概率×影响矩阵 + 行动清单 4 维 + 资金准备 3 大类 + 免责声明
5. 渲染顺序：主体 10 节 → 附录 A → 附录 B → 附录 C → 数据来源 → 免责声明

## 多地址对比模式

**触发**：用户输入包含 2+ 个候选地址。

**输入**：
```json
{
  "mode": "compare",
  "addresses": [
    {"brand": "蜜雪冰城", "address": "地址 1", "city": "北京", "category": "奶茶", "expected_rent": 30000, "expected_area": 30},
    {"brand": "蜜雪冰城", "address": "地址 2", "city": "北京", "category": "奶茶", "expected_rent": 25000, "expected_area": 30}
  ]
}
```

**输出**：1 张对比矩阵 + 1 份综合推荐 + N 份精简报告（仅摘要卡 + 财务 + 风险 + 行动清单）。

**对比矩阵字段**：

| 对比项 | 地址 1 | 地址 2 | ... | 加权 |
|---|---|---|---|---|
| 月租（元）| ... | ... | ... | 越低越好 |
| 周边 500m 竞品数 | ... | ... | ... | 越少越好 |
| 日均人流 | ... | ... | ... | 越高越好 |
| 同位置关店案例 | ... | ... | ... | 越少越好 |
| 财务回本（月）| ... | ... | ... | 越短越好 |
| 风险综合分 | ... | ... | ... | 越低越好 |
| 谈判空间 | ... | ... | ... | 越大越好 |
| **综合推荐度** | 🔴 红 | 🟡 黄 | ... | — |
