# 选址分析报告

## 适用场景

- 「我想在 X 城市开 Y 品牌 / Y 品类，候选点位是 Z，帮我分析下」
- 「评估下 Z 地址适不适合开奶茶店」
- 「X 品牌在 Y 城市还能开吗」

不适用：纯品牌战略研究、行业趋势分析（用专门的研究 skill）。

## 输入要求

字段定义见 `skill.json` 的 `input_schema`。必填：`brand` / `address` / `city` / `category`。选填：`expected_rent` / `expected_area`。

**输入格式**：JSON（推荐）或自然语言。LLM 需把自然语言解析为 `input_schema`，解析失败字段用下方 Fallback 规则。解析后向用户确认 1 次必填 4 字段即可启动。

**Fallback 规则**（用户输入缺失或异常时）：

| 字段 | 缺/异常 | Fallback |
|---|---|---|
| `brand` = 「未指定」 | 报告改「品类适配分析」章节，财务模型按品类基准（客单价/食材成本率取品类中位） | 不可阻塞 |
| `address` 模糊 | LLM 解析为「{城市}{商圈}」粒度，标注"地址粒度为商圈级" | 不可阻塞 |
| `city` 缺失 | 从 `address` 推断 | 自动 |
| `category` 缺失 | LLM 基于品牌推断 | 自动 |
| `expected_rent` 缺失 | 用字段 13 公开房源中位数 | 自动 |
| `expected_area` 缺失 | 用品类基准（奶茶 25㎡、咖啡 40㎡、快餐 50㎡、正餐 80㎡、麻辣烫 40㎡、烘焙 50㎡）| 自动 |

**Step 0 输入扩展**（多问 3 个问题，写入附录 C）：

| 问题 | 用途 | 写入 |
|---|---|---|
| 你有多少启动资金？准备亏多少月必须停？ | C-6/C-7 资金与止损 | C-6/C-7 |
| 你做过餐饮/咖啡/茶饮吗？有合伙人吗？ | C-6 行业经验 + 团队 | C-6 |
| 你接受月租多少钱？免租期/转让费能谈吗？ | C-3 合同谈判目标 | C-3 |

用户不答：照常渲染附录 C，对应字段写「用户未提供，建议自行评估」+ 行业基线参考值。

## 工作流

### Step 0.5：主语锁定（Hard Constraint）

解析用户输入后第一件事锁定主品牌 / 主品类 / 主地址 / 客单价（推算），全文围绕主品牌展开。

1. 财务模型、关键执行建议、行动清单必须针对主品牌
2. 行业基准中其他品牌数字只能做对标引用，不进入主财务模型
3. 「主品牌 vs 替代品牌」对比必须单开附录 A 子章节
4. 「如果换品牌为 X」仅作 1 句背景说明，不展开测算

### Step 0.6：数据时效分级系统（Hard Constraint）

报告所有数据必须标时效，过期数据不能当决策依据。

| 等级 | 时效 | 决策参考性 | 标注 |
|---|---|---|---|
| 🟢 | < 6 月 | 直接可用 | `🟢 \`YYYY-MM\`` |
| 🟡 | 6-12 月 | 可用，建议复核 | `🟡 \`YYYY-MM, 已 X 月\`` |
| 🟠 | 1-2 年 | 决策前需现场验证 | `🟠 \`YYYY-MM, 已 X 年\`` |
| 🔴 | > 2 年 | 仅作历史参考 | `🔴 \`YYYY-XX, 已 X 年, 仅作历史参考\`` |

数据分类：

| 标注 | 含义 | 是否过期 |
|---|---|---|
| 📌 | 历史事实（建成/改造/开业/政策发布时间）| 不 |
| ⏱️ | 经营现状（客流/关店/月销/政策执行）| 会 |

**报告头部必备数据时效分布表**（4 档 + 占比），**硬指标**：🟢 + 🟡 ≥ 80%；🔴 ≤ 10%。

### Step 1：按字段触发联网搜索

读取 `references/report-schema.md` 字段定义，对每个字段触发对应 prompt（见 `references/web-search-prompts.md`）。24 个字段跨主报告 10 节、附录 A、附录 C。

**多地址对比模式**：用户输入 2+ 个候选地址时启用，输出 1 张对比矩阵 + 1 份综合推荐 + N 份精简报告（仅摘要卡 + 财务 + 风险 + 行动清单）。

### Step 2：整合搜索结果

关键约束：

- 禁止用模型记忆填充，所有数据必须来自本次 web_search
- 字段搜不到 → 写「未找到公开数据」，不编造
- 不允许改动用户输入的品牌名/地址/品类
- 关店案例必须限定 2024-2026 年 + 同品类 + 同城市

平台能力边界（web_search 拿不到）：小红书具体笔记、大众点评具体页面、抖音具体视频、微信公众号全文、实时数据。

### Step 2.5：财务反推 + Verdict 自动调整

| 财务结果 | 动作 |
|---|---|
| 月净利润 ≤ 0 | verdict 改 🔴 红，verdict_reason 写明「月净利润为负」 |
| 回本周期 > 24 个月 | verdict 改 🔴 红，verdict_reason 写明「回本周期超 X 月」 |
| 回本周期 12-24 个月 | 保持 🟡 黄 |
| 回本周期 ≤ 12 个月 | 保持 verdict，交叉验证其他维度 |

### Step 2.5.1：3x3 财务敏感性矩阵（Hard Constraint）

单变量敏感性不够，必须做 3x3 矩阵（客单价 × 房租 × 客流，9 场景）。

**默认档位（v1.1.0 放宽版）**：

| 维度 | 悲观 | 基准 | 乐观 |
|---|---|---|---|
| 客单价 | × 0.85 | 主品牌基准 | × 1.15 |
| 房租 | × 0.7 | 同商圈中位 | × 1.4 |
| 客流 | × 0.75 | 推算基准 | × 1.15 |

**档位理由**（v1.1.0 变更）：
- 客单价 ±15%：覆盖蜜雪类下沉品牌价格战 (-15%) / 精品品牌升级 (+15%)
- 房租 -30% / +40%：覆盖拿铺溢价（商场招商旺季 +40%）/ 主动压价（关店案例多 -30%）
- 客流 -25% / +15%：覆盖疫情/施工/冷启动 (-25%) / 营销红利/网红打卡 (+15%)

输出至少 1 个客单价档位的 3x3 矩阵，每个格子标"月净利润数字"（如 `+0.4 万` / `-0.5 万`）。关键发现必须标：亏损/临界/健康场景数 + 盈亏平衡日销量。

**极端场景补充（可选，决策压力测试）**：

对资金敏感 / 高风险品类 / 大额投资场景，建议额外跑 3 个极值场景：

| 场景 | 客单价 | 房租 | 客流 | 触发条件 |
|---|---|---|---|---|
| 黑天鹅 | × 0.7 | × 1.5 | × 0.5 | 疫情/重大政策变化/长期施工 |
| 严重踩空 | × 0.85 | × 1.4 | × 0.75 | 拿铺溢价 + 客流未达预期 |
| 超级乐观 | × 1.15 | × 0.7 | × 1.3 | 网红效应 + 议价成功 |

**不通过处置**（3x3 矩阵 9 格中）：
- 7-9 格亏损 → verdict 必须 🔴
- 4-6 格亏损 → verdict 保持 🟡 但需在摘要卡明示"高失败风险"
- ≤ 3 格亏损 → 可正常推进

**极值档位数据来源**：`references/category-baseline.md` 第 4 节"3x3 财务矩阵的基准应用"。

### Step 2.5.2：概率 × 影响 风险矩阵（Hard Constraint）

风险评分用「概率 × 影响」双维度。6 维度：拆迁 / 政策 / 竞品 / 客流 / 财务 / 品类适配。

| 概率 | 影响 | 风险分（0-5）|
|---|---|---|
| 低 | 低 | 0.05 |
| 低 | 中 | 0.10 |
| 中 | 中 | 0.30 |
| 中 | 高 | 0.40 |
| 高 | 中 | 0.50 |
| 高 | 高 | 0.60+ |

6 维加权和 = 风险综合分（如 `1.25 / 5` 🟡 中风险）。

### Step 2.7：完整标签系统（Hard Constraint）

每条关键数据必须标 4 个标签。

**标签 1：来源等级（5 级）** — 🏛️ 官方 / 📊 行业 / 📰 媒体 / 🏪 平台 / 👤 UGC。多源引用标最高级；平台数据需标"挂牌价"；UGC 仅辅助参考。

**标签 2：置信度（3 级）** — 🟢 高（多源+官方/行业） / 🟡 中（单源+行业/平台） / 🔴 低（单源+自媒体/推算）。

**标签 3：推算依据** — 所有 LLM 推算数字标"推算方法 + 依据基准"。

**标签 4：决策可执行性（3 级）** — ✅ 立即可签 / ⚠️ 需现场验证后签 / ❌ 数据不足。

应用规则：每条关键数据点必须有来源等级 + 置信度；推算数字必须有推算依据；关键结论必须有决策可执行性。

### Step 3：渲染报告

按 `references/report-schema.md` 输出规范渲染 Markdown。

**渲染条件**：

| 章节 | 触发条件 |
|---|---|
| 报告主体 10 节 | 始终渲染 |
| 附录 A「换品类建议」 | verdict = 🔴 且原因为「财务」 |
| 附录 B「数据局限」 | 始终渲染 |
| 附录 C「决策深度分析」C-1~C-8 | 始终渲染（即使数据为空也给框架）|
| 数据来源 | 始终渲染 |
| 免责声明 | 始终渲染（Hard Requirement）|

**渲染顺序**：主体 10 节 → 附录 A → 附录 B → 附录 C → 数据来源 → 免责声明。

输出位置：当前工作目录的 `site_report_<地址简写>_<品类>_<日期>.md`。多地址对比模式输出 `site_report_compare_<N>个地址>_<日期>.md`。

### Step 3.1：行动清单（成本/收益、风险评估）

行动清单按 3 类分：立即做（签约前 1-2 周）/ 验证（签约前 1 周）/ 否决（任一命中红线）。

每条行动 4 维评估：预估成本 / 预期收益 / 风险评估 / 决策可执行性。每个报告必须列 3-5 条否决红线。

### Step 3.2：资金准备清单（Hard Requirement）

| 类别 | 占比 | 包含 |
|---|---|---|
| 开业一次性 | 60-70% | 装修 + 设备 + 原料 + 加盟费 + 保证金 |
| 爬坡期亏损 | 15-20% | 第 1-4 月现金流 |
| 突发风险储备 | 10-15% | 1-2 月突发 |

风险评估：🟢 资金充足 → 可执行；🟡 资金不足 → 现金流压力；🔴 资金缺口大 → 不建议执行。

## 禁止项清单（违反则报告作废，**Hard Constraints**）

### 主语相关
1. 禁止自动延展为其他品牌的财务测算
2. 禁止在「建议」里反客为主（「推荐 X 品牌」不能成为主结论）
3. 禁止未要求的多场景对比 / 跨城市对比

### 内容相关
4. 禁止自动加用户未要求的子报告
5. 禁止把竞品对标错位为主语
6. 禁止在主报告字段里做品牌对比
7. 禁止对用户输入做扩展性解读

### 表达相关
8. 禁止营销味表达（必赚/稳赚/绝对/震撼）
9. 禁止 AI 套路开场（今天分享/我来聊聊/我帮一个朋友）
10. 禁止把行业级宏观内容当结论
11. 禁止模板化填空

### 数据相关
12. 禁止用模型记忆填充
13. 禁止编造数据
14. 禁止改动用户输入

## Step 4：追加免责声明（Hard Requirement）

所有报告必须在末尾追加 `## 免责声明` 章节，模板见 `references/report-schema.md` 末尾「免责声明模板」段。不得省略、不得改写核心条款。4 个部分齐全：数据来源说明 / 使用限制 / 重要提醒 / 授权与免责。

## Step 5：输出自检（Hard Requirement）

报告渲染完成后必须逐项验证，不通过则报告视为不完整。

| 类别 | 检查项 |
|---|---|
| A. 主语锁定 | 主品牌在摘要卡 ≥1 次；财务模型只 1 套（基于主品牌）；关键执行建议 + 行动清单针对主品牌；其他品牌数据仅作对标 |
| B. 禁止项 | 无"如果换品牌为 X"完整测算；无跨城市对比；无营销味 / AI 套路 / 模型记忆 / 改动用户输入 |
| C. 必填项 | 10 节主体；附录 A 触发正确；附录 B 数据局限；附录 C 8 项；数据来源；免责声明 |
| D. 数据时效 | 报告头部有分布表；🟢+🟡 ≥ 80%；🔴 ≤ 10%；🔴 标"仅作历史参考" |
| E. 标签系统 | 关键数据 100% 来源等级 + 置信度；推算数字 100% 推算依据；关键结论 100% 决策可执行性 |
| F. 财务矩阵 | 至少 1 个客单价档位 3x3；每格月净利数字；标亏损/临界/健康场景数 |
| G. 风险矩阵 | 6 维度全覆盖；每维度概率+影响+风险分+依据；综合分 = 6 维加权和 |
| H. 行动清单+资金 | 3 类分；4 维评估；3-5 条否决红线；资金 3 大类；3 档评估 |

**不通过处置**：

- 1-2 项 → 补全/重写对应章节
- 3 项以上 → 报告视为不合格，重新生成
- 主语锁定类不通过 → 必须重写报告
- 数据时效类不通过（🔴 > 10%）→ 必须替换过期数据
- 标签系统类不通过 → 必须补全标签

## 鲁棒性与降级

| 场景 | 行为 |
|---|---|
| `web_search` 不可用 | Step 1 全部字段标「未找到公开数据（web_search 不可用）」，仍渲染 10 节 + 附录 A/B/C；财务模型用品类基准估算，附录 B 明确说明 |
| 字段搜不到任何结果 | 标「未找到公开数据」，不编造；财务模型基于其他字段推算 |
| 用户输入多语言（中文/英文）| **v1.x 中国 only**：仅支持中文输入（英文报告内容用中文模板生成英文翻译）。海外场景 v2.0 支持 |
| 跨 LLM provider（OpenAI / Anthropic / Google / 本地模型）| prompt 模板兼容 Chat / Responses / Messages API；JSON-mode 关闭（非结构化输出）；如模型带 `<think>` 思考块，先剥除再渲染 |
| 单次搜索返回无关结果 | 重写 query 加 `{city}` + `{address}` 限定词，最多 3 次，仍无果则标「未找到公开数据」 |
| 同字段多源冲突 | 优先 🏛️ > 📊 > 📰 > 🏪 > 👤；冲突时在文末"数据来源"标注差异，不静默选边 |
| `references/*.md` 文件缺失 | 仅 1 个文件缺失时，用 SKILL.md 内联规则补足；多个缺失时返回错误并提示用户 |
| `examples/` 缺失 | 不影响 LLM 执行（范本是参考文件），按 SKILL.md + references 仍可渲染报告 |
| **用户用自然语言而非 JSON 输入** | LLM 先解析为 `input_schema`（如「我想在苏州泰华开蜜雪」→ `brand=蜜雪冰城, address=苏州泰华商城, city=苏州, category=奶茶`），解析失败字段用 Fallback 规则；解析后向用户确认 1 次（必填 4 字段）即可启动 |
| **LLM 输出被 token 限制截断** | 优先完成"主体 10 节 + 摘要卡"；附录 A/B/C 与数据来源可分批追加（`## 续 Part 2` 子文件）；免责声明是 Hard Requirement 不可省略 |

## 适用范围

**v1.x 中国大陆 only**：
- ✅ 一线 / 新一线 / 二线 / 三线 / 四线城市（按 `category-baseline.md` 区域差异调整）
- ✅ 6 大品类（奶茶 / 咖啡 / 快餐 / 正餐 / 麻辣烫 / 烘焙）
- ✅ 中文输入 / 中文报告
- ⏳ 县城及以下 / 县级市：基准数据较少，部分字段会标"未找到公开数据"，财务模型可基于行业基准估算
- ❌ 海外城市（港澳台 / 东南亚 / 北美 / 欧洲等）：v2.0 规划中
- ❌ 海外品牌（Starbucks / McDonald's 中国除外）：v2.0 规划中
- ❌ 其他品类（火锅/烤肉/甜品/西餐/日料/茶馆）：未在 baseline，可降级用相似品类基准，但需明示

**输入城市检查**：
- LLM 在 Step 0 解析后必须确认 `city` 在中国境内
- 非中国城市（"纽约""伦敦""东京"等）→ verdict 强制 🔴 + verdict_reason 写明"v1.x 不支持海外场景，参见 v2.0 计划"
- 港澳台 → verdict 🟡 + verdict_reason 写明"港澳台数据可参考大陆基准，但需额外验证政策差异"
