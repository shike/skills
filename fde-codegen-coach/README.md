# 代码生成教练（fde-codegen-coach · FDE 实战营 WS2）

> 把粗版 PRD 和原型变成**可运行的前后端完整应用**——先对齐再生成，20 轮对话保底"跑得起来"。

## 它解决什么问题

让 AI 直接写代码，最容易死在两件事上：**没对齐就开写**（产出和需求判若两物）、**生成到一半失控**（跑不起来、片段式输出）。本 Skill 用工程方法兜住：

- **一致性是硬约束**：每轮生成代码前，先声明【本轮对应：PRD 第 x 条 / 原型第 N 屏】；学员提 PRD 之外的需求，记入【偏离清单】并反问"替换掉哪一条？"
- **保底闸门**：第 12 轮自检主流程是否可跑通——不能则进入保底模式，范围收敛到最小功能集，保证"能跑、能演示"
- **硬排期**：第 5 轮冻结《方案确认单》，第 15 轮完成全部功能代码，第 18 轮必须能启动，第 20 轮交付运行说明 + 已知缺陷清单（不许写空话）

## 默认技术方案（零依赖，现场零配置）

- 后端 Python + FastAPI；数据库 SQLite（单文件免安装）；前端原生 HTML/JS
- 一条命令启动（如 `uvicorn main:app`），种子数据内置恒润语境（客户、材料价、历史报价）
- "AI 报价草稿"用可替换的模拟模块实现，接口隔离，注明可替换为真实模型调用

## 输出红线

1. 不许只给片段——每个文件完整可运行
2. 不依赖注册、付费或外网服务
3. 主流程与原型一致；"报价发出"等担责环节必须有人工确认动作
4. 必须给出运行命令与演示路径（先点哪里、再点哪里）

## 使用方法

1. 粘贴 `SKILL.md` 全文给 WorkBuddy，附"请加载这个 Skill"
2. 粘贴你们在 WS1 产出的 **PRD 全文 + 原型**，发送 `assets/PROMPT_启动.md` 中的启动语
3. 第 1–5 轮逐条确认《方案确认单》后进入生成——参与表态的每一条，都是你签的字
