# 7 节解读流程

> **版本**: v1.0.0
> **地位**: LLM 解读骨架。每份解读按 7 节输出，确保结构一致。

---

## 整体结构

```
1. 抽卡确认（Step 1a-1b 输出）
2. 抽卡总览（Step 1e 输出）
3. 牌序揭晓（Step 1d 输出）
4. 单牌解读（Step 2 输出，逐张）
5. 牌阵联动（Step 3a 输出）
6. 综合叙事（Step 3b 输出）
7. 行动建议（Step 4 输出，按 intensity 数量）
8. 边界声明（Step 5 输出，Hard Requirement）
```

---

## 第 1 节：抽卡确认

**目的**: 告知用户即将进行什么操作。

**输出模板**:
```markdown
## 抽卡确认

- 牌阵: [牌阵名]
- 牌数: [N] 张
- 问题: [用户 question]
- 解读深度: [light | standard | deep]

我们用 [牌阵名] 抽 [N] 张牌。牌阵含义：[一句话]。
请确认后开始洗牌。
```

---

## 第 2 节：抽卡总览

**目的**: 让用户在看解读前先有整体感。

**输出模板**（参考 `four-elements.md` §V）:
```markdown
## 抽卡总览

- 牌数: [N]
- 元素分布: 🔥 火 [N] | 💧 水 [N] | 🌬 风 [N] | 🌍 土 [N]
- 大阿卡纳: [N] / [总数]
- 宫廷牌: [N] / [总数]
- 整体倾向: [1-2 句话解读元素分布]
- 元素缺口: [1-2 句话指出缺失元素 + 解读方向]
```

---

## 第 3 节：牌序揭晓

**目的**: 把每张 [背] 占位符替换为具体牌（位置 + 中文名 + 正逆位）。

**输出模板**:
```markdown
## 牌序揭晓

**位置 1（[位置名]）**：[中文名]（[英文名] · [正/逆位]）

![中文名](https://cdn.jsdelivr.net/gh/shike/location-skill@main/rider-waite-cn__skillhub/assets/cards/{major|minor}/{slug}.webp)

**位置 2（[位置名]）**：[中文名]（[英文名] · [正/逆位]）

![中文名](https://cdn.jsdelivr.net/gh/shike/location-skill@main/rider-waite-cn__skillhub/assets/cards/{major|minor}/{slug}.webp)

...
```

**位置名**必须从 `references/spreads.md` 对应牌阵的位置表里取，不得自创。

**插图规则**：
- 每张抽到的牌**必须**附图（`![中文名](https://cdn.jsdelivr.net/gh/shike/location-skill@main/rider-waite-cn__skillhub/assets/cards/{major|minor}/{slug}.webp)`）
- 大阿卡纳路径：`assets/cards/major/{slug}.webp`（如 `the-fool.webp` / `the-magician.webp`）
- 小阿卡纳路径：`assets/cards/minor/{slug}.webp`（如 `wands-1.webp` / `cups-7.webp`）
- slug 必须与 `references/78-cards.md` 速查表完全一致
- 图加载失败 → 退化为文字牌 `**[XX牌 · 正位]**`

---

## 第 4 节：单牌解读

**目的**: 逐张解读每张牌在当前位置下的含义。

**输出模板**（每张牌）:
```markdown
### 位置 [N]（[位置名]）：[中文名]（[英文名] · [正/逆位]）

![中文名](https://cdn.jsdelivr.net/gh/shike/location-skill@main/rider-waite-cn__skillhub/assets/cards/{major|minor}/{slug}.webp)

- 元素: [火/水/风/土]
- 数字: [0-21 / 1-14]
- 关键词: [3-5 个关键词]
- 牌义: [200-300 字的解读，参考 `references/78-cards.md` 对应牌的含义，结合当前位置 / 问题]
```

**单牌解读插图规则**:
- `light` / `standard` intensity：**每张牌都插图**
- `deep` intensity：**可选插图**（建议每 2-3 张插 1 张图，避免 10 张图刷屏；如用户要求"每张都看图"则全插）

**禁止项**:
- 不得用 LLM 自由发挥——必须基于 `references/78-cards.md`
- 不得给出"你一定会 / 你一定不会"的绝对预测
- 不得给出医疗 / 法律 / 投资建议

---

## 第 5 节：牌阵联动

**目的**: 牌与牌的呼应、冲突、支撑关系。

**输出模板**:
```markdown
## 牌阵联动

- 元素呼应: [N 张火 / 水 / 风 / 土 + 缺失元素 + 解读]
- 数字呼应: [成对 / 序列 + 解读]
- 大阿卡纳关系: [若有大阿卡纳，看其主题的呼应]
- 正逆位分布: [N 张正位 / M 张逆位，解读整体倾向]
- 关键呼应: [列出 2-3 个最强的牌-牌呼应 / 冲突 / 支撑关系]
```

---

## 第 6 节：综合叙事

**目的**: 200-500 字的连贯解读，呈现"这些牌在一起说了什么"。

**输出模板**:
```markdown
## 综合叙事

[一段连贯的 200-500 字叙事，呈现整体解读]

要求：
- 不堆叠每张牌的解读
- 围绕用户问题主轴
- 用第一人称"你"
- 不预测绝对结果
- 不堆营销词
- 不引入新信息
```

---

## 第 7 节：行动建议

**目的**: 给用户 0-2 条可执行的轻量建议。

**输出规则**（5 档 intensity）:
- `very-light` intensity: **0 条**（一句话回答，不给建议）
- `light` intensity: **0-1 条**（极轻量，可选）
- `standard` intensity: **1 条**
- `deep` intensity: **1-2 条**
- `very-deep` intensity: **2-3 条**

**输出模板**:
```markdown
## 行动建议

1. [接下来 7 天内可执行的具体动作]
2. [可选第二条]

要求：
- 时间窗: 接下来 7 天
- 动词: "可以考虑" / "你可以试试" / "值得花时间" / "或许值得"
- 不强制: 不说"你必须" / "你一定要"
- 不预测: 不说"这样做一定会 Z"
- 不渲染恐惧: 不说"如果你不做 X 会 Y"
```

**示例**:
> 接下来 7 天，可以考虑在周二或周三给自己留 30 分钟独处时间，把这次抽牌中"隐者"那张想对你说的话写下来。

---

## 第 8 节：边界声明（Hard Requirement）

**目的**: 标明塔罗的局限与娱乐性质。

**输出模板**:
```markdown
## 边界声明

1. **娱乐性质**: 本解读仅供娱乐参考，不构成任何决策依据。
2. **专业领域**: 医疗 / 法律 / 投资 / 心理咨询请咨询专业人士。
3. **决策权在你**: 塔罗呈现的是「趋势与可能」，最终决策由你做出。
4. **复现性**: 本次抽卡使用 seed=[值]，可复现本次结果。
```

**禁止项**:
- 不得省略此章节
- 不得改写核心条款
- 不得删去"复现性"段
